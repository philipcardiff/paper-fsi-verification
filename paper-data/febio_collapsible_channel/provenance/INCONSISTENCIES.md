| INC-1 | Clock times written in the plan and results (pre-registration "about 03:50", A1 "about 04:05", A2 "about 04:25", heavy lock "04:20") | They are later than the Slurm start times (S1 03:42:36, F1 03:44:27, D1 03:47:54 UTC) and than the last modification of the plan file (03:47:48), so they cannot be literal clock times (apparently estimates). The plan file was overwritten in place; no earlier version exists. Consistent with the stated order: the audit file (03:41:51) precedes S1; the plan's last modification precedes the D1 job by 6 s. Not verifiable from the files: that the original pre-registration and A1 text preceded the S1 and F1 runs respectively. | LIMITATION |
| INC-2 | The reference suite README says the wall "performs a damped oscillation of period about 0.8 s"; the audit says 0.8 s is the rebound spacing | In the reference CSV (converged): troughs at 0.4685, 1.120, 1.752, 2.371, 2.985 s (spacings 0.652, 0.632, 0.619, 0.613 s); rebound maxima at 0.7905, 1.434, 2.059, 2.676, 3.287 s (spacings 0.643, 0.626, 0.617, 0.611 s). The trough-to-trough period is 0.65 s (the report's 0.650 used 1.119 - 0.4685; my 5-point fit gives 0.652). 0.79 s is the time at which the first rebound maximum occurs, not a spacing (trough to rebound maximum: 0.322 s). So the README's 0.8 s is not reproduced as an oscillation period from the stored CSV; what it denotes is not established. FEBio periods, if ever measured, must use the trough spacing. | RESOLVED for the number, OPEN for the README's meaning |
