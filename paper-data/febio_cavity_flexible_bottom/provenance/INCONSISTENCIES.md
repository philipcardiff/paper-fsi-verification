# Inconsistencies found while reconstructing the evidence record, and how each was resolved

Method: every key number in the original working reports was re-derived from the raw stored outputs (`results/raw/`, Slurm accounting extract in `provenance/slurm_jobs.csv`, solver logs, input hashes) by `scripts/verify_against_raw.py` (68 checks, all within tolerance, see `results/VERIFICATION_LOG.csv`) and `scripts/build_tables.py`. Where a report was wrong, ambiguous or superseded, the publication-facing text of this package (README, `docs/FINDINGS_REPORT.md` and the tables in `results/`) follows the resolution below; the archived working reports in `docs/reports/` are kept verbatim except for path/host sanitisation and carry a banner pointing here.

| id | where | what disagreed | resolution |
|---|---|---|---|
| I-1 | campaign status vs Slurm accounting | "cavity 10/10 runs, 37.9 CPU-h" vs the sum of `sacct` CPUTimeRAW for all cavity FEBio jobs 13809..14025 = 38.09 CPU-h | Difference 0.14 CPU-h = the five failed early inlet attempts (jobs 13856, 13864, 13875, 13881, 13888). Excluding them the sum is 37.95 (= "37.9"). `provenance/slurm_jobs.csv` lists every job; experimental rounds 1+2 sum to 0.727 CPU-h (docs: 0.68 + 0.046). The failed rebuild job 14100 (8 CPU-s) is counted in the 0.68 but is absent from the ledger. Allocated, not used, CPU time (e.g. M3 ran at 423 % CPU on 8 allocated cores on a heavily loaded shared node). |
| I-2 | `CAVITY_MESH_STUDY.md` | M2 "floor error at t = 872.5 s (step 350)" | The M2 log says "beginning time step 349 : 872.5"; 348 steps were completed (last accepted t = 870). M1: 389 completed, failed step 390 (t=975). M3: 286 completed, failed step 287 (t=717.5). Package tables use the log values. |
| I-3 | `fsi_check.json` vs FEBio log | Newton iterations per step "7.14 / max 25" (tool) vs the solver's own 7.15 / maximum 21-22 in a converged step | The tool counts convergence tables including those of the failed last step (26 tables). `results/solver_termination_and_cost.csv` lists both; the solver's own statistics are the ones to quote. |
| I-4 | M3 comparisons | Several statements mix the M3 state at t=500 (last flag-0 state) with the failure-exit state t=717.5, e.g. "pair-mean F_y -5.2494 is -0.02 % from solids4foam" and "F2 observed order 2.7" | -5.2494 belongs to t=717.5 (flag 2, written at the solver-failure exit); at the last accepted xplt state t=500 F2 = -5.2469 (-0.07 % from QM -5.2504); the F2 order is 2.5 with t=500, 2.7 with t=717.5. F1 is -4.9809 (t=500) and -4.9835 (t=715/717.5). All tables here carry the state time and never combine times; M1 t=900, M2 t=750, M3 t=500 are the primary states, M3 t=717.5 is a separate labelled row. |
| I-5 | row-parity amplitude D | M1 0.363 vs 0.3647; M3 0.1335/0.1336 vs 0.1344; C1b 0.415 vs 0.417 vs 0.4207 | Different averaging windows, all computed from the same fields: `ybranch` (all interior floor nodes: 0.3630/0.1713/0.1336 (t=500) / 0.1336 (t=717.5) / C1b 0.4152), the force-reconstruction table (nodes with a defined row 2, 4 end nodes excluded: 0.3647/0.1730/0.1344), C1b attribution rows 1-4, x 2.8-5.2 (0.417) and the stabilisation test window x 2.4-5.6 (0.4207, the pre-registered definition). The window is stated wherever D is quoted; the 0.1335 Pa of the M3 state is the `ybranch` value at t=717.5. |
| I-6 | `CAVITY_PARITY_MODE_CHECK.md`, `CAVITY_SOLVER_FIELD_COMPARISON.md` | The pair-row mean was described as a plausible unbiased estimator and "three independent observables move toward the references"; agreement with solids4foam called circumstantial support | Superseded by `FEBIO_FSI_TRACTION_ASSEMBLY_AUDIT.md`: the pair-row mean equals FEBio's own element-mean surface-pressure definition (F2 = F4 to 5e-8 for planar facets), so it is not an independent estimator; it matches the reference at M3 only (+6.1 % M1, +0.9 % M2). Treated as HYPOTHESIS, never as a corrected result. F2 is not established as the physical interface force. |
| I-7 | pressure alternation scope | `CAVITY_SOLVER_FIELD_COMPARISON.md` calls it a "dead-end cavity phenomenon absent in a straight channel"; `FEBIO_PRESSURE_MODE_ANALYSIS.md` finds it throughout the C1b domain (inlet x<1 roughness 0.395 Pa) | Later analysis governs: the alternation exists across the whole cavity-geometry field; the straight Poiseuille run shows it small (y-alternation 0.0013 Pa) because there is almost no force content to excite the soft modes. The y-alternation amplitude predicted by the linear Stokes emulation for the straight channel (-0.027 Pa) does not match the measured 0.0013 Pa; this was not resolved (stated in the analysis report and carried as a limitation). |
| I-8 | solids4foam "floor pressure 1.28-1.31 Pa" | Quoted in early reports as a solids4foam value | It is F_y/4 m of the force values (5.2504/4 = 1.3126, 5.2266/4 = 1.3067), a mean implied by the force, not a floor-pressure measurement. No solids4foam pressure field was ever available to the investigation. |
| I-9 | early failed inputs | `B0_fluid_f1` and `B0_fluid_straight` cannot be regenerated bit-exactly by the final generator | They differ only in the diagnostic monitor node sets (the original inputs had empty or differently defined monitor sets such as `Mon_x10`/`Mon_x13`); physics and mesh are identical. The original inputs are shipped in `inputs/early_failed_attempts/` with hashes; all other 18 inputs regenerate bit-exactly (`scripts/check_inputs.py`). |
| I-10 | `plate_report.json` | `normal_termination: false`, `iters: 0`, `sum_Ry: 0`, `Ry_over_applied: 0` | The analysis script did not populate termination or iteration fields; the plate-only logs contain "N O R M A L TERMINATION" (parsed by `build_tables.py`). The zero reaction forces are a real negative result (the solid-module log returns exact zeros), not a measurement; force equilibrium of the plate was never verified numerically. |
| I-11 | reference table of PR #22 | The "solids4foam" rows of `reference_levels.csv` mix variants across levels (level 1 equals the #597 quasi-monolithic value, level 2 the partitioned u_y, F_y values equal the #597 rerun); the note column of the ANSYS and COMSOL rows repeats the Tukovic note | Not used. The package compares with the partitioned values (solids4foam verification CSV; the u_y values equal the manuscript text) and the quasi-monolithic #618 values on manuscript main (863b8ba, `paper-data/cavity_monolithic_618`). PR #22 values are used only for Tukovic, ANSYS and COMSOL and are provisional (PR #22 is open); ANSYS/COMSOL Ux and Fx come from the PR #12 summary. The finest ANSYS Fx/Ux (4.1e-5 m, spread 0.009 N/m) is noisier than the coarser levels. |
| I-12 | M3 steadiness | "M3 not steady to 1e-4" vs "M3 steady to 1e-4 m (0.04 %) at t=715" | Both quote the same data differently. The pre-registered criterion (relative spread of u_y over the last 10 %, 1e-4) is NOT met (1.05e-3). The tail is a decaying oscillation (period 44 s, e-fold about 86 s, amplitude +/-1.2e-4 m); the last 50/100/200 s means agree to 1e-5 m. The package says "not steady to the stated criterion; conditional estimate with about +/-2e-4 m". |
| I-13 | solver termination wording | Ledger status "completed-normal-termination" for C1 (fluid-only), which failed its steady gate | The ledger status is the process exit state. The gate record is in `docs/reports/CAVITY_VALIDATION_GATE_AUDIT.md` and `results/TEST_MATRIX.csv` (C2). |
| I-14 | run naming | `C3_fsi_M4` is mesh level M3 (mesh factor 4); the directory suffix is the mesh factor, not the level | The package uses M1 = C2_fsi_pilot_f1 (factor 1), M2 = C3_fsi_M2 (factor 2), M3 = C3_fsi_M4 (factor 4) everywhere in tables, with the run directory name in a column. No mesh level M4 (dx 0.0125) was run. |
| I-15 | experimental diffs | `ppp_v413_experimental.diff` and `ppp_v413_round1_alpha075.diff` | Byte-identical (sha256 d43859c1...); shipped once. The round-2 diff is cumulative against pristine v4.13 (round-1 behaviour is no longer selectable in the final binary). `experimental_src/*.diff` are earlier unapplied sketches whose tangent was judged inconsistent by the derivation report; shipped only as superseded sketches. The round-1 and round-2 diffs apply cleanly to a fresh export of the v4.13 tag (checked with `patch --dry-run` on a scratch copy; the maintainers' source tree was not touched). |
| I-16 | S2 transfer check | Interpreted as showing that "the load transfer is fine" | It feeds FEBio's own face-mean nodal pressure (equal to the F1 vertical force) to the same plate. It confirms the pressure-part self-consistency (0.025 %) but cannot detect an error of the pressure itself and cannot distinguish F1 from F2. |
| I-17 | M1 u_y baseline for the sensitivity runs | C4 compares t=900 runs with the C2 value at t=900 (-0.21195916); the M1 table value is t=972.5 (-0.21196737) | Different times of the same run (differ by 4e-5 relative). Rounding: M2 u_y vs partitioned is -2.25 % from the 6-digit values (-0.226233 vs -0.231445), quoted as -2.2 % in the reports and -2.3 % in the generated tables. Sensitivity table uses t=900 for both; the M1 level value uses its latest accepted state t=972.5. |

Not resolvable from the retained data (carried as limitations, not as findings): no bit-exact proof that the stock binary equals the clean tag (no rebuild-and-compare was done); no solids4foam floor-pressure or viscous-traction field; the cause of the zero reaction forces; the straight-channel y-alternation mismatch of I-7; whether the F2/pair-mean value is the physically correct pressure force.
