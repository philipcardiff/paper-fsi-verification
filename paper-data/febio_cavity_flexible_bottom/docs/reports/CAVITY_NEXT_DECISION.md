## Decision
1. **The cavity is NOT ready for a PR.** It is a documented negative/partial result: the FEBio cavity FSI solution is stable and self-consistent, converges in dx, but about 4-5 % below the solids4foam StVK benchmark in both force and displacement, and no cause is identified. Not claimed: verification, convergence to the benchmark, clean solver completion.
2. **Do not run M4** (about 4 x M3 = 110+ CPU-h; the gap is not a mesh effect), no new mesh matrix, no further sensitivity runs at M1 (K, dt, tolerance are exhausted).
3. **No FEBio run is currently justified.** A resolution-independent 5 % pressure-level gap needs a reference field that does not exist in the repository, not another FEBio solution. The one zero-cost action that is decisive: **obtain from the solids4foam side the converged floor pressure profile p(x) and viscous Fx on the interface at dx = 0.05 (and ideally the fixed-plate force on the undeformed floor)** (ask Philip Cardiff or run the tutorial). Comparing profiles localises the difference (cavity-exit region, left/right asymmetry that also matches the 3.4-4.4 x larger u_x(A)) or shows a uniform offset.
4. **Conditional single experiment, only after item 3** (recorded here, NOT authorised, NOT run): fixed-plate fluid-only C1b at M2 (dx 0.05; 6752 fluid cells; same inputs as the validated C1b except the mesh factor; 4 cores; expected about 25-30 min wall, about 2 CPU-h; K 1e6). Diagnostic value: gives the FEBio fixed-plate floor force and profile at M2 to compare with the solids4foam fixed-plate result from item 3, separating a fluid-scheme offset from a coupling/plate effect. It is worth running only if the solids4foam fixed-plate or profile data arrive; otherwise it answers nothing new.
5. If the profile comparison shows an offset concentrated at the cavity exit/outlet, the next candidates (each one change, M1/M2 size, 2-4 cores, <= 2 CPU-h) are: outlet extended downstream (changes the benchmark: label as diagnostic only); a stabilised-convection variant if FEBio v4.13 provides one. Neither is authorised now.
