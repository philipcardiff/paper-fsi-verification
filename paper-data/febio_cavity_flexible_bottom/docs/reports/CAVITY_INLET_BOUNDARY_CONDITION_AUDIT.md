# CAVITY INLET BOUNDARY-CONDITION AUDIT (read-only, FEBio v4.13)

Source: `upstream/febio-v4.13` (git tag `v4.13`, unmodified checkout), official examples in `upstream/TestSuite/Verify` (fl40, fs10, fs07, fs09, fl37, fl39, fc05, bi08, fl23, fl25, fs19). No simulation was needed for this audit. The generator audited is `tools/make_cavity_fluid_feb.py`.

## 1. Why the `fluid velocity` + `math` inlet evaluated Y = 0 (previous run v3)
Classification: **a genuine v4.13 implementation limitation (not a syntax error, not a generator defect)**; my use of it for a spatially varying profile was the error.

- `FEFluidVelocity::Update()` (FEBioFluid/FEFluidVelocity.cpp) builds a default-constructed `FESurfaceMaterialPoint` per element node and sets only `m_elem` and `m_index = i`. Its own comment says "this is a node index, but we really need a gauss-point index". `m_r0` is therefore (0,0,0).
- `FEMathExpression::value()` (FECore/FEScalarValuator.cpp:118) takes X, Y, Z from `pt.m_r0`. So the **nodal velocity** is the profile evaluated at the origin: 1.5 - 6(0 - 1.5)^2 = -12 (x ramp), uniform. This reproduces v3 exactly.
- `FEFluidVelocity::LoadVector()` (the flux term in the dilatation equation) runs over surface Gauss points, whose `m_r0` is set in `FESurface::Init` (FESurface.cpp:322). So the **flux term uses the correct position-dependent profile** while the **nodal velocity is uniform and different**. The two inconsistent descriptions of the same inlet are a second, independent reason v3 could not be a valid inlet.
- A `vec3` `SurfaceData` map is not a way out of this limitation: `FESurfaceMap::valueVec3d` evaluates `H(pt.m_index)`, i.e. the shape function at **Gauss point `i`**, not at node `i`, and `ParseDataArray` (FEBioMeshDataSection.cpp:906) stores exactly one vec3 per face (`setValue(lid, vec3)` fills all face nodes with the same value). So the map is **face-constant**, the nodal velocity is the average of the adjacent face values (O(h^2) ~1 % local profile error), the flux term sees the face values, and the two are consistent only to O(h^2). This is option B of the brief; it works mechanically but is only an approximation (and it cannot represent the profile at the wall-corner nodes better than the O(h^2) average of the adjacent face values, see section 5).

## 2. Built-in `fluid normal velocity` with `parabolic = 1` (option A)
`FEFluidNormalVelocity::Activate()` -> `SetParabolicVelocity()` -> `FEParabolicMap::Generate()` (FECore/FEParabolicMap.cpp):
1. Builds the inlet surface, finds its boundary nodes (surface edges with no neighbour facet).
2. Keeps as boundary nodes only those whose **all three** fluid-velocity DOFs (`wx, wy, wz`) are `DOF_FIXED` (a node on the boundary with any free fluid DOF is released). This is what makes the thin slab work: the z-face nodes of the slab have `wz` fixed only, so they are *not* boundary nodes and get a natural (zero-gradient) condition in z, while the wall-corner nodes (no-slip + `wz` fixed) are boundary nodes with phi = 0.
3. Solves the surface Poisson problem `-laplace(phi) = 1`, phi = 0 on the boundary nodes (a Poiseuille profile in the plane of the inlet), **normalises the nodal values so the mean of the discretised field over the surface equals 1** (`vbar = Q/A`, computed with the same shape functions used in the load), and scales by the load's constant `velocity`.
4. At each update the nodal velocity is `w = nu * VN` (averaged outward nodal normal times the speed), the flux term `H * VN * da` is added to the dilatation equation (same `VN`, same shape functions: consistent), and `DOF_FIXED` DOFs are not overwritten.

Appropriateness for the rectangular thin slab (checked, not assumed):
- Inlet surface = 10 quad4 facets, 1 m x 0.1 m. Wall-corner nodes (4: two y-ends x two z layers) have all three DOFs fixed -> phi = 0; the other 18 inlet nodes are free. The solution is independent of z (natural BC) and equals the 1D P1 solution across y, which for -phi'' = 1 is **nodally exact** (a quadratic is in the P1 nodal-exact class in 1D). So the profile is the planar Poiseuille parabola sampled at the nodes. `tools/poiseuille_check.py pre` replicates the map: nodal speeds 0, 0.5455, 0.9697, 1.2727, 1.4545, 1.5152, ... (nominal parabola x 1.0101).
- **The 1.01 % factor is real, and it is accounted for:** the map normalises the *linear interpolant* (trapezoid) to mean 1, but the continuum parabola through the same nodes has mean 1/(1-h^2) = 1.0101 (h = 0.1). So the prescribed discrete flux is exactly 1 (per unit depth) while the nodal profile is the continuum parabola of flux 1.0101, for which dp/dx = -12 mu Q/H^3 = -0.12121 Pa/m (not -0.12). Acceptance is therefore tested against the actual prescribed discrete flux and the parabola fitted to the measured nodal profile, not against the nominal Q = 1 value.
- This is a 1D-in-y Poiseuille profile (planar, as required), not the circular-pipe profile; for a 3D slab the profile in z is flat because the slab has no z structure.

## 3. Rim pressure (`prescribe_rim_pressure`)
`Activate()` marks as "rim" the surface-boundary nodes with all three velocity DOFs fixed (the 4 wall-corner nodes) and prescribes their dilatation (`SetRimPressure`) to the **mean dilatation of the inlet nodes whose dilatation DOF is open**. Requirement ("internal nodes present"): the inlet has 18 non-rim nodes, so `neq > 0` and the guard `m_rim.size() == surface.Nodes()` does not trigger. Appropriateness: the exact planar Poiseuille solution has a pressure that is uniform across a cross-section, so prescribing the corner dilatation to the cross-section mean does not conflict with the target solution. It removes the corner dilatation degree of freedom, which is the singular point of the corner no-slip/flux coupling, and it is how the official parabolic examples (fl40, fs10, fs07, fs09, fl37, fl39) are set up. It is an added constraint; its influence on the entry region is part of what the diagnostic measures.

## 4. Official examples used as the template
fl40 ("Parabolic normal flow through 2D rectangular domain"): hex8, K = 1e9, mu = 1e-3, rhoi = 0, `fluid normal velocity` with `velocity = -1`, `prescribe_nodal_velocities = 1`, `parabolic = 1`, `prescribe_rim_pressure = 1`, no-slip walls (`wx, wy` fixed), `wz` fixed on the slab faces, zero dilatation at the outlet. The straight-channel diagnostic uses exactly this construction with my channel parameters. Differences: my K = 1e6 (not 1e9, to stay far above the dilatation noise floor at ef ~ 1e-6; Mach number 1.5e-3), mu = 0.01, `rhoi = 0` as in fl40, ramp 0 -> 1 over 10 s. Sign: the outward inlet normal is -x, the load's positive direction is outward, so inflow is `velocity = -1` (as in all official examples).

## 5. Wall-corner nodes and DOF-assignment conflicts
- Wall-corner inlet nodes (y = 1, 2 at x = 0, both z layers): `wx, wy` fixed by `noslip`, `wz` fixed by `wz`. The load only writes DOFs that are `DOF_PRESCRIBED`: `Activate()` sets `DOF_PRESCRIBED` only where the DOF is not `DOF_FIXED` (`if (node.get_bc(...) != DOF_FIXED)`), and `Update()` only writes `DOF_PRESCRIBED` DOFs. BCs are activated before model loads (`FEModel::Activate`: IC, BC, loads, in that order), so the fixed state is present when the load activates. **No DOF is assigned two different values:** the corner nodes remain at zero; the parabolic map also gives VN = 0 there. This is the conflict that the face-constant inlet (option "a") would have introduced and the reason it was rejected.
- Free inlet nodes: `wx` prescribed to nu_x VN (nu = -x exactly: planar facets), `wy` prescribed to nu_y VN = 0, `wz` fixed by the slab BC. The previous `InletWy` zero-velocity set is not used in this configuration, so `wy` has one owner.
- Outlet: `Outlet` zero dilatation (p = 0); velocity DOFs free; outlet wall-corner nodes are in `NoSlip`. Unchanged from the earlier runs.

## 6. Decision of the audit
Option A (built-in parabolic normal velocity with rim pressure) is defensible: consistent flux/velocity treatment, no conflicting DOF constraints, planar Poiseuille profile exactly representable on the slab, and it is the configuration the FEBio test suite itself uses for 2D-rectangular parabolic inflow. Option B (face-constant vec3 map) is rejected: face-constant profile, O(h^2) mismatch between nodal velocity and flux, and an averaged nodal value at wall-corner nodes. The final diagnostic run used option A (see `CAVITY_POISEUILLE_DIAGNOSTIC.md`).

## 7. Limits of this audit
- Read-only: the behaviour above is derived from the v4.13 source and the official examples; the *run* is what tests it.
- It does not show why the original nodal-Dirichlet inlet (v1/v2/lowRe/straight) diverged. The most likely explanation (not proven) is that nodal Dirichlet velocities omit the inlet flux term of the dilatation equation, which the surface loads provide.
- `FEParabolicMap` uses `m_rt` for geometry, so the map is regenerated in the current configuration at activation only (the inlet is stationary here, which is not a limitation for the fluid-only stage; for the FSI stage the inlet nodes are far from the moving plate).
