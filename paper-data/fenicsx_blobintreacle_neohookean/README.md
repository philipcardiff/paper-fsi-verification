# blobInTreacle with the finite-strain neo-Hookean solid: FEniCSx cross-code check (supplementary evidence)

Status: **supplementary evidence from the same research group and the same AI lineage; a second implementation and cross-code check, not an independent verification and not external validation.** No claim of a defect in solids4foam is made.
Text: `../../supplement_fenicsx_blobintreacle_neohookean.tex` (builds alone with `latexmk -pdf supplement_fenicsx_blobintreacle_neohookean.tex`, or pdflatex, bibtex, pdflatex, pdflatex). The neo-Hookean problem (solids4foam PR #694, total-Lagrangian compressible neo-Hookean solid, traction per current area) is a **different mathematical problem** from the historical linear-geometry blobInTreacle (the historical small-strain audit, `supplement_fenicsx_blobintreacle.tex` and its `paper-data/fenicsx_blobintreacle/`); no value of one is used as a reference for the other and they are never combined in one convergence sequence.

Review lineage: code, preregistration, runs, analysis and one internal numerical audit (verdict QUALIFIED, no blocking finding; the response to its four findings is in `REVIEW_RESPONSE_REGISTER.md`) were produced by AI agents of one model family for the same group that produced the solids4foam reference runs. No human or external review has taken place. The classification of the work is **qualified pass**: qualified cross-code consistency of the steady observables; temporal second-order convergence is not verified.

## Reproduce the tables and the figure
Use `python3 -B -I` so that no `__pycache__` is left behind.
```
cd paper-data/fenicsx_blobintreacle_neohookean
python3 -B -I scripts/analyze_nh.py      # derived CSVs (inputs: the CSVs in data/)
python3 -B -I scripts/make_figures.py    # figures/nh_steady.pdf and .png (needs numpy and matplotlib)
sha256sum -c SHA256SUMS
# with the evidence archive extracted to EVIDENCE_DIR (not in git):
python3 -B -I scripts/extract_from_raw.py EVIDENCE_DIR   # regenerates the six FEniCSx input CSVs
python3 -B -I scripts/extract_phase0.py EVIDENCE_DIR     # regenerates solid_only_apex.csv and law_checks.csv
```
Checked: the derived CSVs and the figure regenerate byte-identically from the input CSVs; the FEniCSx and Phase 0 input CSVs regenerate byte-identically from the extracted archive. Not regenerable from this repository: `s4f_rerun_steady.csv` and `s4f_rerun_time.csv` (extracted from the solids4foam case outputs in the archive by the solver repository's `extract_s4f.py`, which also uses the tutorial's own verification script for the interface-vertex change; both are in the archive), `cpu_ledger_sacct.csv` (a sacct dump, script `ledger_sacct.py` in the archive; sacct is not available outside the cluster) and `pr_text_values.csv` (hand-transcribed from the PR text).

Two small differences from the earlier internal reports, both from recomputing from full-precision values: the observed orders of the FEniCSx solid-only apex increments are 0.90, 1.02 (L1, u_x) and 0.69, 0.74 (L2, u_x) here against 0.89, 1.03 and 0.68, 0.74 in the internal report; the FEniCSx u_x limit is 0.045 % from the limit of the PR-text u_x sequence analysed with the same rule (0.140239), which is 0.044 % from the rounded 0.14024 quoted in the PR. Neither changes a statement. The tight-tolerance repeat (Addendum 1) agrees with the main time series to 6.4e-12 relative over all five observables (the internal report quoted 6e-13 for u_x).

## Retained failed and cancelled runs; reason-3 steps
- No FEniCSx run failed numerically (28 runs: 12 production, 10 Addendum 1, 6 Addendum 2; all reached the end time, every SNES step converged; `data/fe_run_validity.csv`). SNES reason 3 (step-norm acceptance) occurred in D1a (1 step), D1b (106 steps), T0.015625 (4), A1T0.125 (1) and A2T0.015625 (4) and never at steady state.
- One solids4foam attempt was cancelled by the operator: x4, job 17400, 4 cores, 13 min, 0.87 CPU-h (projected beyond its 1.5 h limit under heavy node load); rerun as job 17410 (3 h limit, same settings), completed in 1 h 14 min. The case directory is kept in the archive.

## Known limitations of the evidence (also in the supplement)
- Same group, same AI lineage, internal review only; timestamps self-asserted; Addendum 2's ordering relative to its runs cannot be shown to sub-second resolution.
- The solids4foam interface balance of about 1e-6 comes from the solids4foam authors' own runs and is not reconstructed here. The FEniCSx closure (3e-10 N/m) is an algebraic identity of the weak form.
- The location of the minimum fluid J at x4 was not logged and no field was saved. The sampled minimum (`data/fe_ale_x4_samples.csv`) had changed by less than 2e-4 relative from t = 4 to t = 6; an earlier internal note said it was still decreasing, which is true only in the eighth digit.
- The first-order convergence of the FEniCSx apex u_x and the irregular time convergence below dt = 0.0156 are unexplained. Excluded for the latter: SNES tolerance (Addendum 1) and the backward-Euler start-up (Addendum 2).
- Limits depend on the assumed order at the 0.1-0.5 % level (`data/limit_sensitivity_to_order.csv`); no further spatial level was run.
- The preregistration text is hash-bound and shipped verbatim: it contains local absolute paths (section 0, the code location), and its deliverables list (section 8) names an internal reply text as not posted and a possible placement in the PR #69 supplement, both superseded by the decision to publish the neo-Hookean results as this separate supplement; none of this can be changed without changing the hash. The raw run records in the archive also contain local paths (run configuration, SUBMIT_CMD).

- Pressure drop: inlet minus outlet pressure; FEniCSx uses the boundary mean of the inlet trace, solids4foam the inlet face value (equal to the adjacent-cell value for its zero-gradient inlet condition). It is compared at the extrapolated limits only; the coarse-level dp values stay in the data files (`steady_matched_differences.csv`) without a like-for-like claim.

- SNES reason-3 steps by run: D1b 106, D1a 1, T0.015625 4, A1T0.125 1, A2T0.015625 4; none at steady state (`data/fe_run_validity.csv`). The steady dt-independence (D1a and D1b against S1: 7.7e-8 and 1.01e-7 relative) was obtained with these step-norm acceptances in D1b.
- Legacy tests: job 17440 (log in the archive, no test names) shows 3 passed (`test_bdf2_coupled.py`, `test_jacobian_fd.py` as submitted); the internal audit reports 8 passed in `test_svk.py`, `test_driver_exit.py`, `test_ale_time_rates.py` on a login node. The whole tree was not run.
- Figure: only `figures/nh_steady.*` is used in the supplement; an earlier time-study figure was removed as unused (the data are in `data/time_study_t1.csv`).
