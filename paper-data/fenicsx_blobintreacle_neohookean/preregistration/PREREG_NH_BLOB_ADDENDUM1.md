# Addendum 1 to PREREG_NH_BLOB.md (written and hashed BEFORE the runs below; main campaign results were already seen)

Reason (PREREG section 7: a change in response to an observation is a new, labelled run): the main campaign (commit a30ce8c, driver as frozen) showed (i) at x4 the global minimum J of the deformation is 0.19 (below the 0.2 value used in V7), which is in the fluid ALE mesh (fluid cell area ratio 0.41, fluid scaled Jacobian 0.32) while the solid cell-averaged J stays >= 0.77, but the solid NODAL minimum J was not logged separately, so V7 (a solid criterion) cannot be evaluated exactly from the main runs; (ii) the t = 1 temporal differences of u_x at dt <= 0.0156 (1.4e-5, 6.0e-6, 3.9e-6) stop decreasing at the expected rate (successive-difference orders 2.02, 3.09, 1.21, 0.63), so V5 (orders of the first two pairs in [1.6, 3.0]) fails formally for u_x (3.09), and the question is whether the stagnation is a nonlinear-solver tolerance floor (SNES rtol 1e-9, atol 1e-10, with a few reason-3 steps) or a time-discretisation property.
Changes: the driver (`run_blob_nh.py`) only gains logging (solid and fluid nodal J, columns Jmin_solid, Jmax_solid, Jmin_fluid, Jmax_fluid) and two options (`--snes-rtol`, `--snes-atol`, default unchanged). No numerical change at default settings. These runs are labelled A1, are not substitutes for the main runs, and the main-run results stay in the report unchanged.

Runs (Slurm, same rules and cap as the main campaign; estimated 1.7 CPU-h):
- A1S0.5, A1S1, A1S2, A1S4: exactly the S runs (dt 0.04, t_end 6, 2/2/4/8 ranks) with the extended logging. Purposes: solid nodal J for V7, and an exact repeat of the S runs as a reproducibility check (expected: apex and force values identical to the main runs within 1e-10 relative; the CPU time is a second cost sample).
- A1T-tight: the six T runs (x1, dt = 0.25 ... 0.0078125, t_end 1, 2 ranks) with `--snes-rtol 1e-12 --snes-atol 1e-13`. Prediction: if the stagnation is a solver-tolerance floor, the u_x changes keep their second-order scaling (orders in [1.6, 3.0] for all pairs and no reason-3 steps); if not, the orders stay as in the main run (differences at the 1e-7 relative level between the two sets) and the stagnation is attributed to the time discretisation (single backward-Euler first step, mesh-velocity/ALE treatment) without further claims.
Acceptance: V1 and V6 as in the main preregistration. The A1T-tight orders are reported next to the main ones; neither set is replaced.
