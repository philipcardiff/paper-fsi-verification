## 0. Model definition (matched to PR #694 head 6fa468d56503da711d09135599f85ab18f150513)
- Solid: total Lagrangian, compressible neo-Hookean, W = mu/2 (Ibar1 - 3) + K/4 (J^2 - 1 - 2 ln J), Ibar1 = J^(-2/3) tr(F F^T), 3-D isochoric split with F_zz = 1 (tr C includes the zz term 1); mu = 50 Pa, lambda = 500 Pa, K = lambda + 2 mu/3 = 533.333 Pa; sigma = (mu/J) dev(bbar) + (K/2)(J^2-1)/J I; P = dW/dF (in-plane block); tangent by UFL `derivative` (consistent). sigma_zz is non-zero and not used in the in-plane balance. rho_s = 1.
- The s4f source (neoHookeanElasticMechanicalConstitutiveLaw.C at the pinned commit) was read and transcribed line by line (Phase 0). The tutorial gives E = 145.45454545, nu = 0.45454545 (8 digits), which s4f converts to mu = 50.000000155 and K = 533.33328; the relative offset from (50, 533.3333) is 3e-9 / 1e-7 and is ignored in the FEniCSx runs (documented, not tuned).
- Interface: s4f's total-Lagrangian path applies the traction per CURRENT area (nonLinGeomTotalLagTotalDispSolid.C: `forceP = tracP*magSfCurrent` unless `useUndeformedArea`, default false; `tractionBoundarySnGrad` uses the current normal Finv^T n). This is the exact-Nanson measure, i.e. M1 (power conjugate). The FEniCSx model uses M1 by construction (the total-Lagrangian elastic virtual work shares the fluid test function). M2 (reference-area traction) is NOT used in the new model; the code asserts `interface_measure == "M1"` for `solid_law="nh"`.
- Fluid, mesh, inflow, dt unchanged: rho_f = 1, mu_f = 1, P2-P1 Taylor-Hood fluid with ALE (harmonic mesh motion, inverse-volume weight), gradient-form outlet, inflow u_x = g(t)(1+2y)(1-y), g = (1-cos(pi t/2))/2 for t <= 2 else 1; solid P2 (Q2); monolithic (u, p, d) with PETSc SNES. Meshes: meshes/generated/blob_f{0.5,1,2,4}_quad.msh (sha256 39eebdbb..., 2c8ce4d9..., 599a81e6..., 50e9ac2d...; 150, 600, 2400, 9600 cells = the s4f x0.5..x4 cell counts, identical block topology).
- Time scheme: s4f uses `backward` (second-order, first step backward Euler) for ddt and d2dt2 in both regions. FEniCSx: BDF2 for fluid and solid (the existing `fluid_scheme="bdf2"`, solid BDF2 on the (u, d) system), first step a single backward-Euler step (`--startup-substeps 1`, the OpenFOAM behaviour). No substepped start-up is used.
- Code: /home/sairam/work/fenicsx-blobNH (new worktree of /home/sairam/work/fenicsx-fsi-verification, base master 7eab623). Files: `src/solid/neohookean.py` (new), `src/coupling/monolithic_fsi.py` (additive: `solid_law="nh"`; default behaviour byte-identical for the legacy laws), `benchmarks/blobInTreacle/nh/run_blob_nh.py` (new driver). The code-freeze commit is the commit that contains this file; every run logs `repo_head` and the mesh sha256 in its summary.json.

## 1. Phase 0 outcomes that gate production (recorded before this preregistration)
1. Law checks (`phase0/law_checks.json`): UFL-differentiated P, analytic P and numpy P agree to <= 1e-13 relative over a 20-F set including large strain and compression (J from 0.09 to 2.5); the UFL-derived tangent equals the central finite-difference directional derivative to 3.6e-10 (criterion 1e-6); S = F^-1 P symmetric to 1.5e-16; sigma = P F^T/J matches the 3-D Cauchy formula to 2e-15; rotation invariance of W and covariance of P, sigma to 1e-13; small-strain limit reduces to 2 mu eps + lambda tr(eps) I with the stated mu = 50, lambda = 500 (relative error O(eps), 1.2e-5 at eps = 1e-5); isochoric stress trace free; volumetric part dW_vol/dF = K/2 (J^2-1) F^-T; J -> 0: W -> +inf, hydrostatic term -> -inf (finite for J > 0). Relation: K = lambda + 2mu/3 = E/(3(1-2nu)) with the 3-D E = mu(3 lambda + 2 mu)/(lambda + mu) = 145.4545 and nu = lambda/(2(lambda+mu)) = 0.4545 (planeStress no).
2. Equivalence to the s4f law: OpenFOAM-free C++ transcription of the formulas (and of the E, nu -> mu, K constructor path) agrees with `src/solid/neohookean.py` to 5.6e-15 (sigma) and 6.5e-15 (P) at identical F when the same mu, K digits are used (1e-7 otherwise). In addition the actual s4f law was run in the pinned build (below).
3. Solid-only gate (static half cylinder, base fixed, follower pressure p0 and x-traction tx per current area; loads L1 = (10, 5), L2 = (25, 12.5) Pa) on x0.5..x4 in both codes: apex u_x FE/s4f - 1 = -0.90, -0.52, -0.21, -0.10 % (L1) and -1.97, -1.00, -0.45, -0.21 % (L2), halving per refinement; apex u_y differs by 0.5-1.5 % without a clean trend (both codes converge slowly in u_y, FE order ~0.7-0.8). FE equilibrium closure (applied + base reaction) 1e-13. Gate verdict: PASS for u_x (the law, the total-Lagrangian kinematics and the current-area traction convention give the same apex u_x to 0.1-0.2 % at x4); u_y is reported with its uncertainty only.
4. Smoke tests (x0.5, x1, dt = 0.02, t = 1, 2 ranks): the solver ran to t = 1, every SNES step converged; discrete interface closure (fluid weak force vs solid residual at interface rows, base corners excluded) 1e-12; global solid momentum closure (sum of interface-row and base-row residuals minus inertia) 7e-13. Wall: 15 s (x0.5) and 36 s (x1) for 50 steps on 2 ranks. A defect of the legacy diagnostics was found and fixed in the new driver only: the weak interface force evaluated after `step()` uses the already shifted history, so the legacy "weak" force omits inertia terms in transients; the new driver evaluates it with the pre-step history (steady-state values are unaffected).
5. The pinned s4f build (PR #694 head 6fa468d56 = tutorial-only diff on 206437983, OpenFOAM v2512, PETSc 3.24, build job 17359) reproduces the PR text at x0.5: u_x(3 s) = 0.124852, u_y = -0.012477 (PR: 0.124852, -0.012477); the x1 tutorial run (t = 10) reached u_x = 0.135583 and F = (15.751, -25.062) at t = 9.61 while still running at the time of writing, equal to the PR's regression reference values 0.135583 and 15.7508.

## 3. Observables
Steady (t = t_end = 6 for FEniCSx; t = 3 and the last time of the run for s4f, and FEniCSx also at t = 3 for matching): top-point displacement (u_x, u_y) at (1.5, 0) (FEniCSx P2 nodal value, s4f `solidPointDisplacement` at (1.5 0 0.5)); interface force on the solid (F_x, F_y) = integral of the fluid traction over the interface, exact measure (`F_M1x/y`; s4f: total force of the `forces` function object on the fluid interface patch; per metre span); inlet-outlet mean pressure drop dp (FEniCSx `dp`; s4f: area-weighted mean of the fluid p over the inlet patch minus the outlet patch, from the written fields). Secondary: weak-form interface force (`Fx_fluid_on_solid`).
Transient (t = 1): u_x, u_y, F_x, F_y, dp and the displacement of all interface nodes (`interface_final.csv`) for the time study; the interface change is the l2 norm over the interface vertices of the difference in deformed position between successive dt (as in the tutorial verification script).
Structural deformation: apex displacement history, min and max J of the solid (and all cells), E_solid.
Mesh quality: minimum scaled Jacobian of the deformed fluid and solid cells (quad corner det/(|e1||e2|)) every 10 steps, deformed/reference cell-area ratio extremes, global min J; for s4f: checkMesh of the fluid and solid mesh at the last time.
Interface-force conservation: (a) discrete closure max over steps of |Fwex - Rsex| (fluid weak force on the solid minus solid residual at interface rows, corners excluded; algebraic identity at the SNES tolerance); (b) global solid momentum closure |Rsex + Rb - inertia| (interface-row + base-row residuals minus solid inertia); (c) steady fluid-side direct integral F_M1 vs weak Fwex (consistency, reported); (d) interface power P_M1 -> 0 at steady state; (e) fluid volume balance |Q_in + Q_out + dV/dt| (reported). For s4f the PR's own statement (fluid and solid interface forces balance to 1e-6) is not re-verified here (the FEniCSx M1 closure holds by construction).

## 4. Convergence rules (unchanged from the earlier preregistrations; verification/convergence.py sha256 recorded in the manifest)
`verification.convergence.analyse`: >= 3 levels, monotone (same-sign decreasing successive differences), observed order p in [0.5, 3], no Richardson extrapolation from non-monotone data, GCI with Fs = 1.25 (Celik et al. 2008), both consecutive triples reported when 4 levels exist, h = N_cells^(-1/2) (N = 150, 600, 2400, 9600; refinement ratio exactly 2 as for the s4f levels). "Second order" is claimed only if the observed p of an accepted finest triple lies in [1.8, 2.2]; otherwise the observed p is quoted as is. For the s4f time study the tutorial's own successive-difference orders (ratio log2) are reproduced and the `analyse` rule with h = dt is applied to FEniCSx and s4f alike. Time triples (dt, dt/2, dt/4): (0.25, 0.125, 0.0625), (0.125, 0.0625, 0.03125), (0.0625, 0.03125, 0.015625), (0.03125, 0.015625, 0.0078125). Orders are quoted only for accepted triples; the tutorial's s4f time orders (2.13/2.21 u_x, 2.12/2.00 interface) are reproduced from the rerun, not assumed.

## 5. Acceptance criteria (stated before production)
V1 (validity, per run): `summary.json` reached_end = true and failed = false; every SNES step converged (reason > 0; reason-3 steps counted and listed); EXIT file OK (the launcher's EXIT is checked against the summary and history length, not trusted alone); min J > 0 and min scaled Jacobian > 0 for fluid and solid cells at every sampled step. Failure: any run violating V1 is reported as failed and excluded from convergence analysis (kept in the report).
V2 (steady): over the last 0.5 time units the relative drift of u_x, u_y, F_x, F_y, dp is < 1e-5 at every level.
V3 (time-step independence of the steady state): D1a and D1b agree with S1 (dt 0.04) to <= 1e-5 relative in all five steady observables.
V4 (spatial): for each steady observable the `analyse` verdict (accepted or not, p, extrapolated value, GCI) is reported per triple. No acceptance threshold on p beyond the rules in section 4. Expected from the legacy study and the solid-only gate (stated as predictions): u_x and F_x and dp p ~ 1.5-2; u_y and F_y p ~ 0.7-1.5.
V5 (temporal): FEniCSx observed order of u_x and of the interface change from the first two successive-difference pairs in [1.6, 3.0] (the tutorial criterion), and the last change in u_x < 1e-3 of u_x. Prediction: orders ~ 2 (the single backward-Euler first step is O(dt^2) globally). If the order is outside [1.6, 3.0] it is reported as found.
V6 (conservation): discrete closure (a) <= 1e-6 N/m absolute over all steps of every run; global momentum closure (b) <= 1e-6 N/m; steady |P_M1| <= 1e-6. Failure: any violation is a code or tolerance problem to be explained before any cross-code statement.
V7 (mesh quality): reported; failure if the scaled Jacobian of any fluid or solid cell reaches <= 0 or J <= 0.2 in the solid (listed as a warning, not a failure, between 0.2 and 0.5).

## 6. Cross-code comparison rules (Phase 2)
Matched mesh levels (150, 600, 2400, 9600 cells): the difference is quoted as (FE - s4f)/s4f in % for u_x, u_y, F_x, F_y and dp at each level (s4f from the rerun; the PR-text values are quoted alongside and any disagreement between the rerun and the PR text is stated). Orders: FE p vs s4f p per accepted triple, and the difference. Limits: when both sequences are accepted the difference of the extrapolated limits is expressed in units of the combined GCI, hypot(GCI_FE |f_FE|, GCI_s4f |f_s4f|). Words: "agrees within the combined numerical uncertainty" only if |difference| <= combined GCI; otherwise "differs by X % (k x combined GCI)". No closeness criterion is imposed; a difference is never tuned away (no change of geometry, loads, BCs, fluid or dt to improve agreement). The coincidence rule of the earlier studies applies (agreement between different cell counts is not agreement).
Predictions (recorded now; failed predictions will be reported): (P1) steady u_x differs from s4f by < 3 % at every matched level and the difference shrinks with refinement; (P2) u_y by < 8 %; (P3) F_x, F_y by < 3 %; (P4) at t = 1 on x1 the FE u_x is within 3 % of the s4f value at dt <= 0.0625, with a larger difference at dt = 0.25 expected from the different solid and start-up discretisation; (P5) the FEniCSx steady u_x limit lies within 3 % of the PR's extrapolated 0.14024 m. If P1 or P3 fail at any level the report says so and lists the candidates (cell-centred FV vs P2 FE discretisation, partitioned IQN-ILS tolerance 1e-6 and `additionalMeshCorrection` vs monolithic, solid time discretisation, outlet and mesh-motion differences, P2 vs second-order FV in the corner singularities) without choosing one without evidence.

## 7. Failure criteria and what is kept
A failed, diverged or non-steady run is kept (directory, logs, ledger row, FAILED_RUNS entry) and reported; it is never replaced silently. A change of dt, tolerance or solver option in response to a failure is a new, labelled run recorded in an addendum. A result is not claimed if it depends on a run that failed V1. The launcher's `EXIT OK` is not used as evidence on its own.
